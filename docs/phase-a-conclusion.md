## 关键发现(留档,若重启可跳过全部弯路)

1. **AIRI 桌面版存在"配置与启用分离"的断层**:Provider 卡片上"测试通过"(绿点)只代表该卡凭据有效;会话实际使用的是另一个"当前来源"(高亮边框)的选择,且默认落在 AIRI 官方通道上、不易察觉。语音输入无反馈的直接原因即在于此。
2. **火山/豆包语音无法接入 AIRI(0.11.3)**:豆包语音服务与火山方舟的 TTS/ASR 均为自有协议,无官方 OpenAI 兼容端点(方舟仅 chat 兼容);AIRI 原生"火山引擎"卡片依赖 unspeech 私有中转(unspeech.hyp3r.link),其 SaaS 层不认火山原始凭据(401 grant not found);语音 Key 与方舟 Key 互不通用。自建桥接违反阶段 A"不造轮子"原则。
3. **排查方法论教训**:方舟网关先鉴权后路由,用假 Key 探测任何路径都返回相同 401,不能据此判断端点存在;AIRI 的"配置验证成功"是浅校验。
4. **本机基线(16GB M4)**:系统 swap 常态 ~9.4GB(未跑重活时),AIRI 空闲 8 进程合计 ~1.1GB——若重启本阶段,资源监控应重点盯 swap。
