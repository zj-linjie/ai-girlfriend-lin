# 阶段 A · 20 分钟连续语音对话实测方案

> 目标:在真实使用条件下验证现成 AIRI 链路的体验与稳定性,产出延迟、打断、声画、资源与成本的实测基线,作为 B/C/D 阶段的门禁依据。

## 0. 前置检查(全部通过才开始计时)

- [ ] AIRI 已安装并可正常启动(见 [phase-a-install.md](phase-a-install.md))
- [ ] Chat / Speech / Transcription 三类 Provider 已配置并通过试听/试说校验
- [ ] 麦克风权限已授予(系统设置 → 隐私与安全性 → 麦克风 → AIRI)
- [ ] 使用电源供电,关闭无关大型应用(浏览器多标签、IDE 等尽量退出)
- [ ] 网络稳定(同一 Wi-Fi/有线);记录网络类型
- [ ] 已按 [config/airi-providers.example.md](../config/airi-providers.example.md) 校验清单过一遍
- [ ] API 账户已记下**测试前余额/用量**(截图存本地,不入仓库)
- [ ] 资源监控已启动:`scripts/monitor-airi.sh 5 airi-20min-$(date +%m%d).csv 1800 &`

## 1. 场景与测量口径

计时一律用秒表(手机即可)或带时间戳的屏幕录制。所有数值记入 [phase-a-test-record.md](phase-a-test-record.md)。

### S1 · 首次出声延迟(冷启动)

1. 完全退出 AIRI(`⌘Q`,确认托盘无残留),重新启动。
2. 秒表从**按下启动图标**起跑;进入会话后**说出第一句完整问题**(如"今天天气适合做什么?"),AIRI **开始出声回答的瞬间**停表。
3. 记录总时长,并粗拆:启动→可交互 / 说完→开始出声两段。

### S2 · 多轮对话延迟(暖态)

- 正式 20 分钟对话前,先来 3 轮短对话热身。
- 每轮记录:**说完最后一句 → 角色开始出声**的间隔(首字延迟)。至少记录 10 轮,后续正式对话中继续补记。

### S3 · 打断(Interrupt)—— 5 次以上

- 在 AIRI **说话过程中**打断它(直接开口说新内容)。
- 记录:① 从开口到**它音频停止**的时间;② 停止后有无**残音/回声**;③ 打断后它是否正确接上新话题(不串台)。

### S4 · 停止与恢复

- 使用界面上的停止/静音控制(如 Controls Island 语音开关),确认音频立即停。
- 恢复后继续对话,确认无重复播报、无丢上下文。

### S5 · 文本/语音切换(如支持)

- 语音一轮 → 文字输入一轮 → 再语音一轮,确认模式切换顺畅、上下文连续。

### S6 · 声画同步(嘴型)

- 每隔约 5 分钟观察一次:**说话时嘴型是否动、是否有明显音画错位**;待机时角色是否回到待机动作。
- 有条件则录屏留证(本地保存,不入仓库)。

### S7 · 音频设备切换(如支持)

- 对话中把输出切到蓝牙耳机/再切回扬声器,确认不会断流或静音;麦克风设备切换同理。

### S8 · 20 分钟连续对话(主场景)

- 真实闲聊/问答混合,≥20 轮,不刻意极端。
- 期间出现的一切异常(崩溃/卡死/断流/幻听/答非所问)随手记时间点+现象+是否可复现。
- 期间顺手完成 S3/S4/S6 的抽查项。

## 2. 资源监控

`scripts/monitor-airi.sh` 每 5 秒采样一次所有 AIRI 进程的 CPU/内存与系统 swap,崩溃期间写入 `AIRI_NOT_RUNNING` 占位行。测试结束后用 Excel/Numbers 打开 CSV 观察:

| 指标 | 关注点 | 风险线(16GB 机器) |
| --- | --- | --- |
| 峰值/均值 CPU | 是否持续高位导致风扇狂转、掉帧 | 单进程持续 >150% 需标注 |
| 峰值/均值内存 | 20 分钟内是否线性增长(泄漏) | 增长 >1.5GB 需标注 |
| swap used | 是否开始动用 swap | >1GB 持续增长需标注 |
| AIRI_NOT_RUNNING | 是否出现(崩溃时刻) | 出现即记为稳定性事件 |

## 3. API 成本

- 测试结束后到 Provider 控制台导出/记录本次消耗(DeepSeek 等 Dashboard 有用量页)。
- 换算口径:**本次 20+ 分钟实测花费** 与 **按此频率每天 1 小时的月成本估算**。

## 4. 结果判定(填入 phase-a-test-record.md 后,到 conclusion 文档下结论)

| 维度 | 通过标准 |
| --- | --- |
| 稳定性 | 20 分钟无崩溃;或崩溃 1 次但可复现原因明确且不阻断使用 |
| 延迟 | 暖态首字延迟主观"可日常聊天"(参考:≤3s 舒适,3–6s 可接受,>6s 糟糕) |
| 打断 | 5 次打断全部正确停止,无残音、无串台 |
| 声画 | 无明显错位;待机动作正常 |
| 资源 | 无持续 swap 增长;内存无异常泄漏趋势 |
| 成本 | 记录数值即可(用户自行判断可负担性) |
